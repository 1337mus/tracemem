## LongMemEval

Pins: [repository at `9e0b455`](https://github.com/xiaowu0162/LongMemEval/tree/9e0b455f4ef0e2ab8f2e582289761153549043fc), [README schema and QA interface](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/README.md#L75-L106), [QA evaluator](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/src/evaluation/evaluate_qa.py#L24-L43), [QA metric aggregation](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/src/evaluation/print_qa_metrics.py#L12-L33), [retrieval metric aggregation](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/src/evaluation/print_retrieval_metrics.py#L10-L42), and [retrieval metric definitions](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/src/retrieval/eval_utils.py#L4-L46), plus [LICENSE](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/LICENSE#L1-L21). The former unmapped evaluator digest exactly matches `src/evaluation/evaluate_qa.py`; the former metrics digest exactly matches `src/evaluation/print_qa_metrics.py`.

**README says.** Each release variant has 500 question records. It lists six `question_type` values, marks abstention items with a `question_id` ending in `_abs`, and describes `answer_session_ids` as evidence-session labels. Turns with `has_answer: true` are the evidence-turn labels. The README describes `longmemeval_s` as about 115k history tokens, `longmemeval_m` as about 500 sessions, and `longmemeval_oracle` as containing only evidence sessions. These are README claims; no data files were read.

**Code verified, answer scoring.** The evaluator reads hypothesis rows with `question_id` and `hypothesis`, looks up `question`, `answer`, and `question_type` in a reference file, and warns then skips hypothesis IDs absent from the reference. Its judge aliases are dated GPT-4o and GPT-4o-mini, or Llama 3.1 70B served through a local OpenAI-compatible endpoint. The prompt asks for a yes/no correctness decision. The temporal prompt accepts off-by-one day, week, or month counts. The knowledge-update prompt accepts an updated correct answer even when old information is also present. The preference prompt asks whether the response correctly recalls and uses the user's information, without requiring every rubric point. An `_abs` ID switches to the unanswerable-question prompt. The API request uses temperature 0 and a 10-token output limit. The code labels a result true when the judge text contains the substring `yes`, case-insensitively.

The evaluator averages labels overall and by question type. The separate QA aggregation script also reports task-average, overall, and `_abs` accuracy. That aggregator asserts that every stored judge model is exactly `gpt-4o-2024-08-06`, although the evaluator itself accepts the other aliases. The overall and type averages include abstention rows; the `_abs` score is also reported separately.

**Code verified, retrieval scoring.** The README says retrieval evaluation skips the 30 abstention instances because they have no answer location. The metric printer filters IDs containing `_abs`. For session results it reports `recall_all@5/10` and `ndcg_any@5/10`; for turn results it reports those cutoffs plus `recall_all@50` and `ndcg_any@50`. The helper defines `recall_any` and `recall_all` over the supplied evidence IDs and computes NDCG with binary relevance. Its DCG helper leaves the first item undiscounted and discounts later items by `log2(2), log2(3), ...`, so the first two positions both have weight 1. The turn-to-session helper expands the ranked prefix until it contains k unique sessions (or exhausts the corpus), but keeps repeated session IDs in the projected corpus for NDCG. Preserve these implementation conventions when comparing against this pin; a different library's NDCG formula may differ.

**Comparison consequence.** Choose and report the same history variant. Oracle history contains only evidence sessions, so it does not measure the same retrieval task as S or M. For QA, hold the target system, history supplied, and judge alias and prompt fixed. For retrieval, hold session versus turn granularity and cutoff fixed. A top-k match alone does not match token cost when the retrieved units differ in length.

## LoCoMo

Pins: [repository at `3eb6f2c`](https://github.com/snap-research/locomo/tree/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376), [README schema and context description](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/README.MD#L8-L26), [QA runner](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluate_qa.py#L19-L114), [answer normalization and F1 functions](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluation.py#L75-L145), [category scoring and evidence recall](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluation.py#L189-L241), and [aggregator](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/task_eval/evaluation_stats.py#L94-L145), plus [LICENSE scope](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/LICENSE.txt#L116-L155) and [attribution conditions](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/LICENSE.txt#L222-L258).

**README says.** The released subset has ten conversations. A sample contains sessions and timestamps, speaker and dialogue IDs, turn text, generated observations and session summaries, event summaries, and `qa` rows with `question`, `answer`, `category`, and evidence dialogue IDs when available. The README describes its QA model context as a truncated conversation. For RAG, it names dialogue, observation, and session-summary databases. It also says the repository does not release image files, while image URLs, captions, and search queries are present in the dataset. These are README statements; the dataset and image references were not fetched.

**Code verified, answer scoring.** `task_eval/evaluate_qa.py` loads a JSON list of samples, takes the system-under-test model as an argument, and writes per-sample QA rows. It supports GPT, Claude, Gemini, and selected Hugging Face model families. It does not call a second model to judge answers. The evaluator assigns the answer metric field a `_f1` suffix.

The score implementation normalizes case and punctuation, removes commas, articles, and the word `and`, then stems tokens with Porter stemming. Categories 2, 3, and 4 use token F1. Category 1 splits prediction and answer strings on commas and averages, for each reference part, its best token F1 against the prediction parts. Category 3 uses only the answer text before the first semicolon. Category 5 returns 1 if the response contains `no information available` or `not mentioned`, case-insensitively, and 0 otherwise. The category comments group 2, 3, and 4 as single-hop, temporal, and open-domain; the code applies the same token-F1 path to all three and contains no separate temporal tolerance rule.

For RAG evidence recall, the scorer checks the returned context IDs against the annotated evidence IDs. If context IDs begin with `S`, it compares evidence by session ID; otherwise, it compares dialogue IDs. If the context key is absent or the evidence list is empty, it appends recall 1. This default affects the reported recall and should be accounted for when interpreting results. A present but empty context list with nonempty evidence instead raises at `context[0]`; the fallback of 1 does not cover that input. The runner rounds each answer score and recall to three decimal places before the aggregator computes the micro-average over question counts by category.

**Comparison consequence.** LoCoMo's evidence recall is the fraction of annotated evidence IDs found in returned context, with a value of 1 when the context key is absent or evidence is empty. LongMemEval instead reports binary all-evidence recall and NDCG at explicit cutoffs, at session or turn granularity. These recall values are not interchangeable. LoCoMo's default RAG top-k is 5 in the runner, but k does not establish equal token budgets across dialogue, observation, and summary units. The README states that full-context QA uses a truncated conversation; the exact truncation and prompt rules live outside the evaluator files inspected here.
